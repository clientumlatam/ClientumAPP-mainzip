Make the main ClientumOS workspace navigable at /app
What & Why

The prioritized plan identifies stable deep navigation as the first milestone. ClientumOS already has Clerk authentication, Wouter routing, a portal shell, and many working views, but the current experience is centered on /user-portal and tab state. Moving the authenticated workspace to /app will make the product shareable, reload-safe, and ready for the rest of the sitemap.
Done looks like

    /app opens the authenticated dashboard.
    /app/crm, /app/whatsapp, /app/analytics, /app/erp, /app/configuracion, and the other primary areas resolve through URLs.
    Existing /user-portal and /crm links redirect without breaking.
    The sidebar changes the URL and reloads the correct view.
    Basic 404 and access-denied states exist.
    Existing modules continue to work through the new route structure.

Prioridad: crítica
Objetivo: que ClientumOS tenga una arquitectura de URLs estable antes de agregar nuevas funcionalidades.
0.1 Crear un registro central de rutas

Definir una única fuente de verdad para:

    Ruta.
    Nombre visible.
    Módulo.
    Permiso requerido.
    Si es pública o privada.
    Si debe indexarse.
    Alias legacy.
    Vista asociada.

/app/crm/contactos
/app/analytics
/app/configuracion

Esto evita mantener rutas dispersas en el sidebar, el router y el registro de vistas.

Los tabs internos deben conservarse para estados secundarios, pero las áreas principales deben tener URL propia.

Ejemplo:

/app/crm/pipeline?view=table
/app/app/erp?section=inventario

La URL debe preservar:

    Filtros.
    Vista kanban o tabla.
    Registro seleccionado.
    Página actual.
    Parámetros de búsqueda.
    Segmentos activos.

0.5 Crear páginas de sistema

Antes de ampliar el producto:

    Página 404.
    Página de acceso denegado.
    Estado de carga.
    Estado de error.
    Página de sesión expirada.
    Redirección posterior al login.
    Fallback para rutas no reconocidas.

Criterio de finalización de la Fase 0

    /app abre el dashboard principal.
    Todas las vistas actuales tienen URLs profundas.
    Recargar una URL mantiene la vista correcta.
    Los enlaces antiguos siguen funcionando.
    El sidebar navega mediante rutas, no solamente mediante estado interno.
